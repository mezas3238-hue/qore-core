## Core distinction

GEN-C13 separates three things that must never be collapsed:

```text
observed post-outcome episode
        !=
retrospective simulated counterfactual
        !=
prospectively identified causal effect
```

The existing GEN-C13 V1 engine is correct to force:

`causal_effect_identified = false`

for retrospective counterfactual studies.

A simulation saying "deploy less would have looked better" is hypothesis
generation, not causal proof.

## Chronology firewall

For every memory episode:

1. the original decision must be frozen before its outcome;
2. the outcome must be reconciled before the memory item exists;
3. phenotype/counterfactual analysis may begin only after the outcome;
4. the memory item may influence only later chronological hypotheses;
5. no memory item may be fed backward into the episode that created it;
6. no historical decision or outcome may be rewritten.

## Evidence levels

### Level 0 — descriptive phenotype

Examples:

- PROFIT_GIVEBACK;
- CAPITAL_STARVATION;
- OPTIONALITY_DESTRUCTION;
- OVERCOMPOUNDING.

Allowed claim:

`DESCRIPTIVE_ASSOCIATION`

Forbidden claim:

`CAUSE`

### Level 1 — retrospective counterfactual simulation

A governed simulator may compare a different action on the already-finished
episode.

Allowed claim:

`HYPOTHESIS_WORTH_PREREGISTERING`

Forbidden claims:

- causal effect identified;
- winning counterfactual;
- production recommendation;
- automatic config mutation.

### Level 2 — prospective causal ablation

A retrospective hypothesis may become a causal candidate only by creating a new
preregistered treatment identity for **future** eligible decisions.

The comparison must obey:

`CIBO_COMPOUND_CAUSAL_ABLATION_PROTOCOL_V1`

Required:

- treatment frozen before eligible decision outcomes;
- exactly one changed mechanism;
- identical causal eligibility population;
- identical provider/Risk/CMA surface;
- identical provider-economics semantics;
- same causal horizon and coverage;
- no pre-freeze decisions;
- no outcome-selected treatment rule.

Only results from the later prospective population may contribute to causal
identification.

### Level 3 — replicated causal economic evidence

A prospective treatment is not considered robustly identified until:

1. the non-compensatory economic gate is satisfied;
2. required adversarial stress passes;
3. the same treatment replicates independently in
   `WF1 / WF2 / WF3 / WF4`;
4. no fold uses retrospective relabeling or pooled rescue.

If any fold fails, the treatment is not robustly replicated.

## No same-episode causal upgrade

A retrospective GEN-C13 counterfactual object can never be upgraded in place
from:

`causal_effect_identified = false`

to true.

If later prospective evidence supports the hypothesis, it must be represented
by a separate causal-evidence lineage referencing:

- the original hypothesis/memory item;
- the new treatment identity;
- treatment freeze SHA;
- future decision-population SHA;
- provider-economics SHA;
- OOS/stress/replication evidence.

The old counterfactual remains retrospective forever.

## Memory-use ablation

The economic value of **using memory itself** must also be tested prospectively.

Valid control:

the same frozen capital policy without the specific preregistered
memory-conditioned hypothesis input.

Valid treatment:

the same policy with exactly that memory-conditioned input enabled for later
eligible decisions.

Nothing else may change.

This is the only admissible route to claim that GEN-C13 memory improves future
capital decisions.
