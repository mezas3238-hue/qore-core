## Economics invalidation

PR #518 produced a valid historical *baseline of that exact implementation*, but not final economics for Revision 3.2. Timing, entry family, stop family, target family, lifecycle, LTF profile and daily selection are all methodology-sensitive variables. R3.2 changes several of them, therefore #518 economics cannot be reused for Trader Lab qualification or `DEMO_ELIGIBLE`.

The historical #518 run remains retained for falsification, regression and before/after comparison only.

## Cardinality finding retained from #518

The ~16,179 figure is a diagnostic candidate universe, not 16,179 trades. In the exact #518 run, `mechanical_candidate_count` is the length of the candidate list and a single H4 anchor can append C2-long, C2-short and/or C3 candidates. The aggregate separately counts automatic setups and fills. The architectural defect is different: PR #518 has no market-day authority that mechanically prevents multiple selected/fill events if more than one automatic setup arises on the same day.

## Required replacement boundary

The canonical reconstruction path is:

`R3.2 source evidence -> shared source kernel -> split Forex/Futures authority -> timing profile -> independent LTF profile -> diagnostic candidates -> source-coherent bundle -> daily selection authority -> max-one market-day execution -> H4 lifecycle -> research outcome`.

No rule may be promoted merely because it improves P&L.
