## 1. Constitutional decisions

### 1.1 OANDA Practice is withdrawn as a required project dependency

```text
OANDA PRACTICE
!= REQUIRED QORE DEMO FOUNDATION

OANDA PRACTICE WITHDRAWN
!= PROVIDER CERTIFICATION ABANDONED

ONE PROVIDER UNAVAILABLE
!= QORE ROADMAP BLOCKED
```

The provider-specific MISSION-03 OANDA Practice activation path is superseded as an active prerequisite. Existing OANDA-specific source, tests, workflows and documents remain historical repository artifacts until separately adjudicated; this amendment does not authorize destructive deletion.

Issue #146 must be closed as `not planned / superseded` only after this amendment is integrated and post-merge verified. It must not be represented as successful OANDA certification.

Future live/demo provider certification must be provider-neutral at the constitutional layer and instantiate provider-specific evidence only through certified adapters/capabilities.

### 1.2 Productive QORE-owned Cloud Fabric is mandatory

The existing QORE hosting/runtime/lease/fencing/health/orchestration/failover contracts are architectural foundations. They do not constitute a productive cloud substrate.

```text
MISSION-08 CONTRACT FITNESS
!= PRODUCTIVE QORE CLOUD

QORE IS THE HOSTING / VPS / CLOUD SERVICE PROVIDER
QORE CLOUD FABRIC IS A FIRST-CLASS PRODUCT INFRASTRUCTURE DOMAIN
EXTERNAL CLOUD IS OPTIONAL SUPPLY, NOT QORE SERVICE AUTHORITY
```

QORE must be capable of operating its service plane on infrastructure owned/operated under QORE authority. External hardware vendors, carriers, colocation, cloud overflow or federation may be replaceable supply boundaries; none becomes QORE strategic authority.

### 1.3 CIBO is the CEO personal intelligence assistant

CIBO is elevated from a structured executive-dialogue surface to a first-class executive intelligence role.

Canonical role:

```text
CIBO
=
CEO PERSONAL ASSISTANT
+
GLOBAL MARKET INTELLIGENCE OFFICER
+
OPPORTUNITY DISCOVERY ENGINE
+
RISK-ADJUSTED REVENUE ADVISOR
+
TRADER DEVELOPMENT DIRECTOR
+
EXECUTIVE EXPLAINABILITY INTERFACE
```

CIBO must understand the governed financial universe represented by QORE, interact naturally and proactively with the CEO, coordinate specialist knowledge, identify risk-adjusted revenue opportunities, identify when QORE should not trade, and supervise/teach Traders through validated learning processes.

Authority remains constitutional:

```text
CIBO RECOMMENDATION != CORE DECISION
CIBO CONVERSATION != EXECUTION AUTHORITY
CIBO TRAINING != PRODUCTION SELF-MODIFICATION
CIBO OPPORTUNITY != GUARANTEED PROFIT
CIBO KNOWLEDGE != SPECIALIST-DEPARTMENT AUTHORITY
```

## 4. Mandatory Program I — QORE-Owned Cloud Fabric

Program I becomes a mandatory construction program before final Production Roof certification.

### I-01 — Cloud Fabric Architecture Freeze

Freeze:

- physical/virtual substrate boundary;
- host/node identity;
- cluster/cell/region model;
- tenancy/isolation model;
- network zones;
- storage classes;
- security/secret dependency boundaries;
- artifact/image provenance;
- placement/capacity authority;
- Department 16 ownership.

### I-02 — Compute / Host Lifecycle

Implement and certify:

- compute inventory;
- node enrollment;
- host lifecycle state;
- maintenance/drain state;
- capacity facts;
- immutable host evidence.

### I-03 — Virtualization / Runtime Isolation

Implement one or more certified execution substrates for hosted QORE runtime units.

Requirements:

- tenant/account/runtime isolation;
- bounded resource authority;
- no neighboring tenant authority leakage;
- reproducible runtime image/version identity;
- fail-closed unknown state.

No specific Kubernetes/container/VM technology is made constitutional merely by this roadmap; implementation technology must be selected and independently certified against the contracts.

### I-04 — QORE Network Fabric

Implement:

- network segmentation;
- controlled ingress/egress;
- service identity transport;
- encrypted authenticated service links;
- provider/gateway egress boundaries;
- observability;
- regional/proximity placement support.

### I-05 — Storage / Replication Fabric

Implement bounded durable storage capabilities with explicit ownership, replication, backup, restore and corruption/recovery evidence.

No distributed store becomes universal authority merely because it persists data.

### I-06 — Secrets / Keys Operational Substrate

Department 2 retains trust/security authority. Department 16 implements the Cloud operational substrate.

Requirements include:

- opaque references outside the secret store;
- least privilege;
- rotation/revocation;
- audit evidence;
- encryption at rest/in transit;
- no secret material in logical values/logs/evidence packages.

### I-07 — Artifact / Image Supply Chain

Implement:

- versioned immutable runtime images/artifacts;
- provenance;
- integrity verification;
- promotion gates;
- rollback identity;
- compromise containment.

### I-08 — Scheduler / Capacity / Placement

Implement governed placement without granting trading intent.

```text
PLACEMENT != TRADING DECISION
CAPACITY != EXECUTION AUTHORITY
```

Must support cells/pools/regions, bounded blast radius, account/runtime placement and noisy-neighbor containment.

### I-09 — Deployment Control Plane

Compose existing hosting orchestration with productive infrastructure adapters.

It may prepare/drain/contain/stop runtimes according to certified contracts. It may not create BUY/SELL intent or execution authority.

### I-10 — Runtime Registry + Execution Lease/Fencing Composition

Productively compose existing runtime-registry and account-scoped lease/fencing contracts.

Requirement:

```text
AT MOST ONE ACTIVE FENCED EXECUTION AUTHORITY PER TRADING ACCOUNT
```

### I-11 — Account Execution Unit Hosting

Implement hosted account execution units supporting the client mobile-only operating model without requiring the client phone to remain online.

### I-12 — Cloud Observability / Incident Evidence

Compose Department 15 observability and incident operations with Department 16 infrastructure evidence.

### I-13 — Backup / Disaster Recovery

Implement and prove:

- backup;
- restore;
- regional/cell recovery;
- reconciliation before writer transfer;
- no duplicate writer/order authority after recovery.

### I-14 — Cloud Security / Tenant-Isolation Certification

Independent adversarial certification of:

- tenant isolation;
- service identity;
- secrets;
- network segmentation;
- privilege;
- artifact provenance;
- compromise containment;
- blast radius.

### I-15 — Cloud Reliability / Failover Certification

Prove degraded modes, failover, fencing, stale-state behavior, recovery and reconciliation.

### I-16 — Cloud Latency Certification

Where market/provider paths are latency-sensitive, measure with retained provenance:

- decision-to-runtime;
- runtime-to-gateway/provider;
- acknowledgement;
- end-to-end distributions;
- jitter/tail latency;
- orchestration overhead outside the hot path.

```text
NO MEASURED PROVENANCE -> NO NUMERIC LATENCY SLA
```

### I-17 — Cloud Scale / Capacity Certification

Only measured evidence may support numerical capacity claims. The architecture must remain horizontally extensible and cell-based where justified.

### I-18 — Cloud Operational Demo Certification

Prove productive infrastructure behavior in a non-real-capital environment before Production authority.

### I-19 — QORE Cloud Final Integration Gate

Requires exact-head CI, independent architecture/security review, operational evidence, protected integration, post-merge verification and inclusion in final Program-H system certification.

## 5. Mandatory Program J — CIBO Executive Intelligence & Trader Development

Program J becomes a first-class construction program under Department 13 + Department 20 boundaries, using Departments 4–14 as governed sources and never becoming a parallel sovereign.

### J-01 — CIBO Role / Authority Contract

Freeze CIBO's role, accepted inputs, emitted outputs, owned state, prohibited authority and dependency graph.

CIBO owns executive intelligence coordination and personal-assistant state where explicitly certified. It does not own canonical market facts, pricing truth, Risk policy, Portfolio authority, Order authority or Settlement truth.

### J-02 — Executive Conversation Session Boundary

Extend the existing structured dialogue model with governed conversation/session contracts:

- conversation/session identity;
- CEO principal binding;
- turn/correlation continuity;
- read scope;
- evidence scope;
- context retention policy;
- expiry/freshness;
- sanitized public answer material.

Raw free text/voice remains an adapter concern until sanitized/structured.

### J-03 — Text Conversation Adapter

Implement natural-language text ingress/egress without giving the language model direct governance or trading authority.

### J-04 — Voice Conversation Adapter

Implement optional speech-to-text/text-to-speech adapters under the same authenticated executive session and evidence boundaries.

Voice recognition does not grant authority by itself.

### J-05 — Executive Intent Classification

Classify CEO input into bounded categories such as:

- read/question;
- explanation;
- navigation;
- request for recommendation;
- proposed governance action;
- unsupported/ambiguous request.

Any command-like intent must be converted into a proposed action and independently enter the authenticated MISSION-04 executive command path.

### J-06 — Global Market Knowledge Fabric

CIBO consumes governed QORE semantic/market/research/valuation/risk/portfolio evidence across all certified market families.

Required cross-asset scope grows with Program-D certified coverage, including material cash/money-market, FX, equities, funds, indices, fixed income, rates, futures, options, forwards, swaps, commodities, credit, securities financing, volatility, crypto, structured/hybrid/multi-leg/synthetic and future certified families.

CIBO must not hard-code a narrow provider symbol list as its financial ontology.

### J-07 — Market Regime Intelligence

Implement evidence-backed regime classification/uncertainty surfaces without allowing unvalidated model output to become productive authority.

### J-08 — Opportunity Discovery

Continuously identify candidate risk-adjusted economic opportunities across certified markets.

Candidate analysis should retain, where available:

- market/family;
- thesis identity;
- evidence;
- expected-return methodology reference;
- uncertainty/confidence;
- liquidity;
- capacity;
- transaction costs;
- downside/tail risk;
- regime dependence;
- relevant constraints.

```text
OPPORTUNITY CANDIDATE != TRADE DECISION
```

### J-09 — Opportunity Ranking / Revenue Advisory

CIBO may rank and present opportunities to the CEO and specialist processes.

Its mission is to seek risk-adjusted revenue opportunities, not to guarantee profit.

```text
EXPECTED RETURN CLAIM -> METHODOLOGY + DATA PROVENANCE + REPRODUCIBILITY
```

### J-10 — No-Trade / Capital-Withdrawal Intelligence

CIBO must identify when evidence supports not trading, reducing risk, pausing a research thesis or withdrawing capital from a degraded opportunity.

This is as important as opportunity discovery.

### J-11 — Proactive CEO Assistant

CIBO may initiate executive communication when certified conditions warrant attention:

- material opportunity;
- material risk;
- system degradation;
- trader degradation;
- conflicting/insufficient evidence;
- incident;
- significant market/regime change.

Proactive communication is a notification/dialogue action, not a governance mutation.

### J-12 — CIBO Executive Daily / Weekly Intelligence

Produce evidence-backed CEO briefs covering opportunities, risks, system state, trader state, research changes and unresolved uncertainties.

### J-13 — Trader Registry

Represent governed Trader identities and roles including, where applicable:

- human Trader;
- AI Trader;
- virtual Trader;
- research Trader;
- shadow Trader;
- specialist Trader.

Trader identity does not itself grant productive authority.

### J-14 — Trader Capability / Specialty Profiles

Retain versioned capability/specialty claims, instrument/family scope, permitted environments and certification state.

### J-15 — Trader Performance Evidence

Build evidence-backed Trader performance/quality records including, when methodologically valid:

- decision quality;
- execution quality;
- risk-adjusted performance;
- drawdown;
- regime performance;
- calibration;
- mistakes;
- missed opportunities;
- attribution uncertainty.

No performance number without provenance/reproduction.

### J-16 — Trader Skill / Degradation Detection

Distinguish, where evidence supports it:

- bad luck/noise;
- poor execution;
- strategy degradation;
- regime mismatch;
- data failure;
- overfitting;
- capacity saturation;
- insufficient evidence.

CIBO may recommend keep/retrain/reduce/shadow/suspend/review/retire, but authority changes must pass the owning governance chain.

### J-17 — Trader Coaching / Curriculum

CIBO may issue evidence-backed training/coaching material and curricula tied to observed weaknesses, market knowledge and replay examples.

### J-18 — Replay / Simulation Training

Training must use governed research/replay infrastructure with retained datasets, exact versions and reproducible outcomes.

### J-19 — Trader Learning Candidate

Any learned change is a candidate artifact, never immediate Production mutation.

Canonical promotion chain:

```text
OBSERVATION
-> LEARNING CANDIDATE
-> RESEARCH
-> REPLAY / BACKTEST
-> OOS
-> STRESS
-> RISK REVIEW
-> CIBO REVIEW
-> INDEPENDENT VALIDATION
-> VERSIONED PROMOTION
```

### J-20 — Trader Versioning / Promotion

No trader may self-rewrite productive behavior. Promoted behavior must be versioned, auditable and independently validated according to the applicable authority chain.

### J-21 — Cross-Trader Knowledge Synthesis

CIBO may synthesize specialist findings across Traders and markets while retaining source lineage and uncertainty.

### J-22 — CIBO/Trader Interaction Boundary

Implement bounded dialogue/task/feedback contracts between CIBO and Traders. CIBO can teach, request analysis and coordinate work; it cannot bypass Core/Risk/Portfolio/Execution authority.

### J-23 — CIBO Security / Prompt-Injection / Data-Leakage Certification

Independent adversarial tests must cover:

- prompt injection;
- privilege escalation;
- secret disclosure;
- evidence spoofing;
- stale/context-confused answers;
- cross-tenant leakage where applicable;
- command bypass attempts;
- malicious market/provider content;
- hallucinated authority.

### J-24 — CIBO Market-Knowledge Conformance

Prove that CIBO consumes certified owner contracts and does not flatten materially distinct products or invent unsupported operational support.

### J-25 — CIBO Opportunity Methodology Certification

Any quantitative opportunity ranking used beyond descriptive research must satisfy Program-G methodology, lineage, OOS, reproducibility and promotion gates.

### J-26 — CIBO Executive Command Handoff Certification

Prove:

```text
CEO TEXT/VOICE
-> CIBO INTERPRETATION
-> PROPOSED EXECUTIVE ACTION
-> CEO AUTHENTICATED CONFIRMATION WHERE REQUIRED
-> MISSION-04 EXECUTIVE REQUEST GUARD
-> AUTHORIZED INTENT
-> COMMAND DISPATCH
-> GOVERNANCE MUTATION
-> AUDIT EVIDENCE
-> CIBO PUBLIC CONFIRMATION
```

Never:

```text
CEO UTTERANCE -> LLM -> DIRECT MUTATION
```

### J-27 — CIBO Full-System E2E

Prove executive conversation, cross-market intelligence, opportunity research, trader coaching, command handoff, evidence and read-model behavior without creating trading authority.

### J-28 — CIBO Independent Certification / Integration Gate

Exact-head CI, independent security/architecture/product-quality review, Integration Gate, protected merge and post-merge verification are mandatory.
